## Task E: environment hardening for every child process

`GitEnvironment` (95b6e1c) strips inherited repository-locating variables from the app's git spawns only. Other
child processes still inherit the server's whole environment:
- the agent CLI;
- the one-shot CLI calls;
- stdio MCP servers;
- node leaf tools;
- the capability sandbox;
- llama-server and the measurement children.

What to do:
- Find every spawn site.
- Decide, per site and with a stated reason, what to strip:
  - `GIT_*` repository variables for anything that may run git: the claude CLI does, the agent's Bash does;
  - `NODE_OPTIONS` for node children, since it can inject `--require` into the sandbox;
  - anything else that redirects a child's state.
- Keep what a child legitimately needs (PATH, `CLAUDE_CONFIG_DIR`, the app's own variables).
- One shared helper, never a copy per site.
- The sandbox matters most: an inherited `NODE_OPTIONS=--require …` would load code before `cap-guard.mjs`. Verify, and test it with a real attempt paired with a positive control.
- Test coverage: e2e for each class that is drivable, confirmed to fail without the strip; the rest stated.

## Run 12: sentence-boundary windows inside our segmenter

Run 10 found mMiniLMv2 BETTER under Lyntai's D177 on both fixtures (long 182 → 196, mixed 184 → 198), concentrated
where the answer is late in a note. The untested reading is that a piece cut at a sentence boundary splits an answer
less often than a fixed-position window. D177 cannot carry our pace, so the question is whether OUR
`ChunkedScoreProvider` should cut its windows at boundaries.

What to do:
- Build it behind the chunking knob as a measurement mode first:
  - same budget, same ≤5 windows, same ≥25% overlap, and the last window still at the tail;
  - each window's edges snapped to the nearest sentence end, then line break, then whitespace, inside a stated slack;
  - NFKC handling unchanged.
- Pre-register:
  - arms `rrk` (as shipped) against `rrb` (boundary), per reranker, on the long, mixed and short fixtures;
  - **rule:** ship boundary windows as the default only if mMiniLMv2 is significantly better on long `all` found@8, no reranker is significantly worse anywhere (positions, mixed short targets), and short facts are byte-identical;
  - otherwise the mode stays a knob and the notes say so.
- If it ships: household text, rules and `RerankInputCap`'s docs follow.

## Run 14 and Task D: retire the embed gate

The gate (`EmbedderReadyAsync` before a back-fill) exists because a write whose vector fails still pays its
annotation. Lyntai 3.5's `GraphMemoryOptions.SkipAnnotationWithoutVector` (Part 304) ends that. Turned on alone,
though, it would leave facts whose input the embedder REFUSES (past its 2,048-token window) unannotated for good,
because our classifier keeps them and never retries. So:

- **Run 14.** Measure D177 segmentation on `llamacpp-embed` (`MaxInputChars` plus `Segmentation`; pieces pooled into a length-weighted mean vector) on facts past the window. Can an over-window fact now get a vector, and does semantic recall find it (a paraphrase whose wording sits past the old cut)? Use a one-fact capability check plus a small fixture of long notes. Record the recall quality for pooled vectors against none, and the latency.
- **Task D, only if Run 14 holds:**
  - enable segmentation on the embedder and `SkipAnnotationWithoutVector`;
  - make the classifier's "input refused" branch unreachable for llama.cpp, or keep it as a fallback;
  - retire the pre-flight quota gate, keeping a startup warning source when the embedder does not answer;
  - update the rules (workaround (3) CLOSED) and the tests;
  - the built-in embedder truncates at 2,048 tokens and never refuses: say what applies to it.
