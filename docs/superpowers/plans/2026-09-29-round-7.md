## Task S: an OS sandbox for the planner agent — research first, then an owner decision

**What is left open today.** The jail's integrity rests on three legs (`.claude/rules/dev-conventions.md`, *Data folder
discipline*): Edit/Write/Read cannot reach `state/` (solid); the Bash path-token scan (best effort); no nested shell (best
effort). A constructed token or a nested shell that slips past the last two can, in an EXECUTE run where a Bash exists:
- overwrite `state/agent/scope-guard.mjs`, neutering the guard until the next boot;
- read `state/`: the access token, the TLS key, the database.

Code inside an agent-authored script, and exfiltration through a fetched URL, are the same class. A low-privilege
service account was DECLINED (`docs/ROADMAP.md`): the claude CLI authenticates per user, so a different account breaks
the login the product rests on.

**The constraint the owner set:** the sandbox confines only the ESCAPE ROUTES. It must not take anything the agent uses:
Bash (Git Bash), network egress (WebFetch, `scrape`), the scoped file tools, the knowledge base, the loopback MCP
channel, and nested `node --permission` capability sandboxes. What it must deny:
- reads under `state/` (token, TLS key, DB, the guard, the settings files);
- writes to the guard and to the generated `--settings`;
- writes anywhere outside the data folder's write set.

**Research spike (0 tokens, no model calls).** Evaluate, on this Windows 11 machine and as the SAME user:
1. **AppContainer, or less-privileged AppContainer (LPAC).** A per-app SID, with `internetClient` for egress and ACL
   grants to that SID on:
   - the CLI binary and its config/credential directory;
   - the data folder's record dirs, read and write;
   - `.claude/`, read;
   - Git Bash;
   - node;
   - `%TEMP%`, or a private temp dir.

   `state/` gets no grant. Check that the CLI can still read its OAuth credentials, since AppContainer blocks the
   profile by default.
2. **A restricted token or Low integrity level.** Mandatory labels: data-folder write dirs relabelled Low, `state/`
   and the guard left Medium (so no-write-up). Note that integrity labels stop writes, not reads, so `state/` reads need
   an ACL deny as well.
3. **Job objects:** limits only, no filesystem confinement. Useful beside either of the above, never alone.
4. Windows Sandbox / Hyper-V: expected to be too heavy (a separate OS and login). Rule it out with a reason, not by
   assumption.

For each mechanism, measure:
- `claude auth status` reports signed in;
- a hook-blocked `-p` run starts;
- a Git Bash command runs and its guard hook fires;
- the loopback MCP channel is reachable;
- a `node --permission` capability runs nested;
- `state/` is unreadable;
- the guard file is unwritable;
- a write outside the data folder is refused;
- the startup cost per run.

**How it would plug in.** Lyntai's `ProcessRunner` is sealed. A BYO `IProcessRunner` makes `CliProviderEngine.IsAvailable`
optimistic (dev-conventions, `ChildEnvironment`). The likely seam is a small launcher executable, set as the command in
`LYNTAI_PROVIDER_CMD`, that creates the contained process. That is the same seam the isolation flags already ride.

**Deliverable:** a measured recommendation recorded in `docs/self-managed-llm-runtime.md`, and an OWNER DECISION before
anything is built. Say plainly what each option cannot close.

## Task F: the e2e flakes the 1.4.0 fleet showed

- **p44 fails in the shifted batch, never alone** (6 of 6 alone, once as an abort, once as `fetch failed`). It stops and
  restarts its server on the SAME port three times with a fixed 1.5 s `settle()`, which the authoring rule forbids
  (memory: never stop and restart a server on the same port). Fix: a fresh port per boot, clear of every other suite's
  ports and of Windows' reserved ranges.
- **p21 failed in 1 s as the first shifted suite** right after the parallel main batch (3 of 3 alone). Most likely that
  batch's fixture processes were still exiting. Fix: the runner waits for no `_e2e-` fixture process before the next
  batch.
- **Windows reserves TCP ranges that move** (now 5458–5557, 5768–5867 and 5868–5967). A dozen suites' ports sit inside
  the first. `devtools/_run-shifted.mjs` is a gitignored local stopgap. Make it a committed `dev.mjs e2e --shift`, or
  have the harness pick free ports. Avoid the WHATWG bad ports (6000, 6566, 6665–6669, 6697, 10080).
