## Run 8 — the pace on a CPU

The reranker notes and `next.md` describe what `RerankPace` does on "只有 CPU 等较慢的机器" and add 「这些还没有在只有
CPU 的机器上实测过」. This machine can run llama.cpp with **no GPU offload** (`n-gpu-layers = 0` in the router's preset —
a real CPU run on real hardware, stated as "this machine's CPU", not "every CPU").

**Instrument.** Run 6's long fixture and seed (no tags, 判断 off). Arms on a CPU-only router (a second bench router, or a
per-arm preset override — the bench must record which): BGE and mMiniLMv2, each cut (`rr`, knob off) and chunked with
the pace (`rrk`); plus `formula`, and the GPU `rrk:` BGE as the reference. The pace's activity is the OBJECT here, so the
I6 void guard must be relaxed for designated CPU arms only — recorded per arm, never silently. Record per recall: windows
sent, whether it was cut by the 60 s deadline, the verdict, wall time.

**Report:** found@8/top-1 per position; the count and order of deadline cuts (first recall? how many?); windows per
recall over the run (does the pace converge, to what?); serial latency. **Decision rule:** if on the CPU the chunked+pace
arm is significantly WORSE than the cut arm on `all` found@8 for either reranker, the default on a machine the pace
measures as CPU-slow must change (owner decision, with the numbers); otherwise the household sentences replace "not
measured on a CPU-only machine" with what was measured here.

## Run 9 — long and short facts in one recall

Every reranker note says mixed recalls are unmeasured: a long fact is scored as its BEST window, so with more windows it
has more chances at a high score than a one-window short fact.

**Instrument.** A mixed fixture built deterministically from the existing two (no model): 30 facts kept short (original
text) and 30 turned into long notes (Run 6's construction, answer at `end` or `beyond`), balanced across languages and
across the 240 questions' targets; seed with 判断 off. Arms: `formula`, BGE / mMiniLMv2 / LAMAR each cut and chunked.

**Decision rule:** chunking "costs short facts" if, on questions whose target is SHORT, chunked found@8 is significantly
worse than cut (paired, p < 0.05) for any reranker — then the notes must say so with the number, and a length-aware
fix (e.g. a window-count penalty) becomes a measured follow-up; otherwise the notes' "mixed recalls unmeasured" becomes
the result. Report long-target questions too.
