### 模型搬到「资源」了,「记忆检索」只决定哪一层用哪个

下载一个模型,和下载浏览器、下载 Git 是同一件事 —— 它是一个有体积、有能力、可以删掉的文件,本身对
检索没有任何看法。可之前 Ollama 运行时装在「资源」,跑在它上面的模型却装在两个面板以外的一个讲检索
质量的页面上。

现在「资源 · Resources」里多了一栏**本机模型**:运行时的状态、已下载的模型(标着「嵌入」还是
「对话」、多大、哪一层在用)、可下载的模型对照表,以及一个直接填模型名的输入框。「记忆检索」里不再有
下载和删除按钮 —— 它只剩下真正属于检索的那个决定:**每一层用哪个模型**。

可下载的那张表里现在也有对话模型,不只是嵌入模型。判断用的本机模型和语义用的嵌入模型跑在同一个
Ollama 上,所以一个专门用来下载东西的面板,没有道理在你缺一个对话模型时让你去开终端。

### 每一层自己选后端,能选什么由「谁能干这活」决定

三层现在都是一行:一层、一个后端、一个模型。后端不再是写死的两个按钮,而是「登记了能服务这一层的
那些」——

- **判断**可以跑在 Claude CLI 上,也可以跑在本机的对话模型上。
- **语义**只有本机嵌入模型一个选项 —— 不是我们不让选 Claude,而是 Claude 根本不提供生成向量的接口。

这个区别不只是措辞:以前「能不能用」是一段判断代码,而判断代码是会写错的(上一版就在两个方向上都写
错了)。现在一个后端能出现在某一层,是因为「有一个能服务这一层的实现被登记了」。哪天出现一个既能对话
又能生成向量的模型,它会自己出现在两边,不需要我们改任何东西。

不能用的后端**仍然会列出来**,并写清楚为什么(没装 Ollama / 装了没运行 / 本机只有嵌入模型),需要下载
时直接告诉你去「资源」下载哪一个。把它藏起来等于用「让你没法问」来回答「为什么我选不了这个」。

### 「语义」挪到了「高级」下面

Lyntai 在自己的语料上实测过一件事:漏检里 **0% 是「没检索到」** —— 答案本来就在候选里,只是排在了后面。
所以想让「换个说法也能找到」,先开**判断**比先开**语义**更划算(漏检 0.54 → 0.19)。

面板照这个排:公式和判断在上面,语义收在「高级」里,一次点击就能展开,顶上的状态条依然三层都显示 ——
一层不那么关键,是把它放在后面的理由,不是把它从「现在到底在跑什么」里拿掉的理由。

这份实测写明了**是 Lyntai 的语料,不是这个家庭的**,并且会一直这么写下去,直到有人在这里的资料上真的
量过一次。

### 一个不出声的错:判断用的模型有两个地方能改,而赢的是另一个

「校准」的模型路由里原本有一行「记忆判断」,「记忆检索」里也能改判断的后端。两个控件写同一个值,而路由
那行会**覆盖**另一个。于是:一旦你在那里选过一次 `haiku`,之后又把判断切到本机模型,程序就会拿着
「haiku」这个名字去问 Ollama —— 而标注和核对失败时是**不报错**的,所以真实的现象是一次模型调用都没有,
也没有任何错误,只是检索悄悄地一直没变好。

现在只有一个地方能改:在「记忆检索」里选后端时,模型跟着一起定。「校准」里那一行已经去掉了。

反过来的同一个错也一起修了:旧版切回 Claude CLI 时会**记住**你之前选的本机模型(免得你重新下载一遍),
于是设置文件里可能同时写着「用 CLI」和「模型是 gemma3:4b」。升级后如果照字面读,就会把一个 Ollama 的
模型名交给 Claude —— 面板上会显示成「Claude CLI · gemma3:4b」。老的设置文件现在会被正确地读成默认模型。

### 记忆检索:三层各自叫自己在做的事

**校准 · Cortex → 记忆检索** 里的三层,原来第二层叫 **Claude CLI 增强** —— 可它自己就带着一个把这份工作
交给本机模型的开关,一旦切过去,标题上写的那个后端根本没参与。更别扭的是,那个「本机模型」选项就在
一张叫「本地模型 · Local model」的卡片上方:两个几乎同义的词,一上一下,指的却是两回事。

现在三层都按**做什么**命名,后端变成标签:

| | 做什么 | 跑在哪 |
|---|---|---|
| **公式 · Formula** | 图谱衰减 + 排名融合 + 全文检索 | 始终启用,不需要设置 |
| **判断 · Judgement** | 写入时标注主题,检索时判断哪些结果真正回答了问题 | Claude CLI **或**本机对话模型 |
| **语义 · Semantic** | 为事实生成向量,换个说法也能找到 | 本机 Ollama 嵌入模型 |

标签报的是**正在跑**的那个,不是刚存下的那个 —— 换后端要重启,中间这段时间两者并不一致,顶上会出现
「设置已保存,重启后生效」。以前换判断的后端不会提示重启,现在会。

### 「本机模型」按钮不再无缘无故点不动

判断要用本机模型时,可选的是哪些模型,以前是拿 app 自带的嵌入模型清单反推的 —— 不在清单里就当成对话
模型。这在两个方向上都是错的:

- 如果你装的本机模型**恰好都在那份清单里**,可选项就是空的,「本机模型」按钮直接变灰,而同一个面板下面
  的「本机模型占用」还列着它们 —— 有模型,却切不过去,页面上也没有一句话解释。
- 反过来,一个清单没收录的嵌入模型会被当成对话模型放出来,选中后也拦不住 —— 而标注和核对失败时是
  **不报错**的,结果只是检索悄悄地一直没变好。

现在直接问 Ollama 每个模型能做什么(它本来就会说),按这个筛。清单只在旧版 Ollama 不给这个信息时兜底。
可选项为空时,面板会说清楚是哪种情况:没装 Ollama、装了没运行、还是本机只有嵌入模型 —— 三种情况三个
不同的解决办法。「本机模型占用」里每个模型也标了「嵌入」还是「对话」。

### 下载模型有进度条了

以前点「下载」,按钮写着「下载中…」,然后就没有别的了 —— 一个几百 MB 到几 GB 的下载,期间没有进度、
没有字节数,和卡死看不出区别;而且整个下载是挂在那一次请求上的,浏览器等不下去先放弃的话,已经在下的
模型会被报成失败。

现在下载在后台跑,面板上是一条真正的进度条(整个下载合起来算,不是一层一层地重来),带 Ollama 自己的
状态说明。失败会留在原地写明原因,而不是悄悄消失。

### 「使用」不再是一个默默变灰的按钮

启用一个嵌入模型时,app 会先让它真的算一次向量 —— 算不出来就不保存,免得检索静悄悄地空掉。这一步在
模型第一次载入内存时可能要几十秒,而按钮除了变灰什么都没说。现在它会写「启用中…」,并说明正在等的是
什么。另外,如果 Ollama 已经说了某个模型不能生成向量,现在会立刻拒绝,不用先干等它载入完。
